# First Principles

### Machine learning, rebuilt from the ground up.

Understand the ideas behind the models by deriving and implementing them yourself — one equation, one experiment, and one insight at a time.

---

## The idea

Modern machine learning can feel like a stack of black boxes. **First Principles** is a hands-on journey to open them up.

The goal is to build a growing collection of machine-learning and AI models from their mathematical foundations—not just call a library and accept its output. Each implementation should make the underlying ideas easier to see: what the model assumes, how it learns, why it works, and where it breaks.

This is a learning project in progress. The models below are a **roadmap**, not a claim that every implementation is already available.

## The principles

- **Derive before coding.** Start with the problem, assumptions, and objective.
- **Make the mechanics visible.** Implement the core math and learning procedure rather than hiding them behind a prebuilt model API.
- **Build intuition with experiments.** Use small examples and controlled changes to understand behavior.
- **Test the fundamentals.** Check numerical results, edge cases, and behavior against known examples.
- **Explain the trade-offs.** Document what a model is good at, what it assumes, and when it can fail.

## The learning path

The catalog will grow from foundational ideas toward modern architectures:

| Area | Models and concepts |
| --- | --- |
| **Classical machine learning** | Linear and logistic regression, k-nearest neighbors, naive Bayes, decision trees, random forests, support vector machines |
| **Unsupervised learning** | k-means, Gaussian mixture models, principal component analysis |
| **Neural-network foundations** | Perceptrons, multilayer networks, activation functions, loss functions, gradient descent, backpropagation |
| **Deep-learning architectures** | Convolutional networks, recurrent networks, LSTMs, GRUs, attention, transformers |
| **Generative modeling** | Autoencoders, generative adversarial networks, diffusion models, language-model building blocks |

The exact scope will evolve as the project grows. Each model should earn its place through a clear explanation and a working implementation.

## How a model should be explored

Each implementation is intended to answer a few practical questions:

1. **What problem does it solve?**
2. **What assumptions does it make?**
3. **What is the objective or learning rule?**
4. **How does the implementation map to the math?**
5. **How can we tell whether it is learning correctly?**
6. **Where does it struggle, and why?**

The emphasis is on understanding, not just producing a prediction.

## Project status

This repository is at the beginning of the journey. Implementations and explanations will be added incrementally, with the aim of making each step understandable and reproducible.
